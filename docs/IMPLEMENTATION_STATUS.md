# 实现状态

当前构建：**0.2.0-alpha.1**；存档版本：**0.2.0**；数值：**data-1.0.0-import.1**；生成器：**world-2.0.0**。

用户本轮明确选择：账户与双层星图首版，便于逐版验收。实现范围是 v0.0 底座、v0.1 主要账户流程、以及按定稿世界规则修订的 v0.2。这里不是对原计划所有批次的完整验收声明。

## 已实现

- Node 24 / TypeScript / React / Vite / Express 模块化单体，一个锁文件，固定依赖版本。
- PostgreSQL 17、版本化迁移、重复迁移保护、真实数据库测试及 CI。
- Better Auth 维护密码哈希、HttpOnly Cookie 会话、来源校验、限速与退出撤销；支持注册、登录、退出、改名及修改密码。生产配置启用 Secure Cookie。
- 每账户最多三个活动存档，账户行锁与部分唯一索引共同保证并发限制；删除要求准确名称，软删除并记录审计；创建请求使用幂等键，重试不会重复建档。
- 按 seed 稳定生成九个命名 Region，每区 10–15 个星系，每星系一个恒星及 2–6 个行星。
- 实际连通航线、稀疏区内骨架及长环路、相邻 Region 的 1–3 条桥接边；没有以方框显示 Region。
- 双层 SVG 星图：选择、双击进入、编号搜索、星域高亮、标识开关、缩放、拖动、复位、扩大视图、返回母星。
- 服务端隐藏未知名称、资源与槽位。恒星只含 ID、类型和坐标，不生成资源、所有权或海盗装备。
- 母星固定 Medium / 120 / 7 槽、铁铀保障；只读初始设施和 E 侦察/战斗舰档案。
- 完整保留四份来源资料，导出 11 张 XLSX 表及本阶段使用的 10 矿种、27 船体、30 等级记录。
- 响应式布局、键盘选择、对话框焦点约束与 Escape 关闭。
- 补充本机 Docker Compose 试玩、Windows 双击启动器与 macOS/Linux shell 入口，不要求玩家另外安装语言运行时。

## 当前边界

- 初始货币、等级、设施及舰船是本阶段只读初始状态；世界作为 JSONB 快照持久化。生产版开始前需新增 PlayerState、Facility、Ship 等独立状态实体迁移。
- 没有 tester/admin 管理、固定测试场景或开发快进；自动化测试使用随机临时账号且不会操作真实游玩账户。
- 审计页目前仅展示创建/删除存档。登录安全审计、设备会话管理与权限角色还需后续账户批次补全。
- 未实现生产、研究、装备、航行、A/B/C 情报、战斗、维修、殖民、弃置与成长；不能将此构建称为 v1.0 游戏。
- 未提供公开部署、邮箱验证、密码找回、账户删除、备份管理界面、72 小时长期运行验收或 126 场战斗回归。
- 已引入世界快照版本；不支持未知未来版本读取。未来生成器变更不能重新生成旧档，必须显式迁移。
- 测试通过不等同于用户已完成个人试玩。代码已提交并推送至 GitHub main；未打发布标签，未部署公网服务。
