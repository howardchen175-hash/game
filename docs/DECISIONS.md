# 架构与规则决议

## 001 · 交付阶段

用户选择先交付账户和双层星图。采用 TypeScript 模块化单体：React 19、Vite 8、Express 5、PostgreSQL 17、Better Auth 1.7。具体补丁版由 package.json 与锁文件固定。认证交由库实现，不自行设计密码或会话加密。首版使用邮箱而非另增用户名凭据。

## 002 · 世界结构冲突

实施计划和体验文档仍有旧 3×3/81 网格描述，定稿规范第四章明确取消网格，采用九个命名 Region、银河全局坐标、星系内局部坐标及实际 systemRoute。XLSX 没有与新拓扑相冲突的节点/航线表。本版采用定稿双层结构；Region 标签只代表归属，不绘制方形边界。

区内使用最小生成树，额外边只连接原先至少四跳的节点，形成长环路。横纵相邻 Region 各生成 1–3 条桥接边，并保留一条 R1↔R9 长程边。坐标以左下角为原点，SVG Y 轴在显示时翻转；恒星始终是局部 (0,0)。

## 003 · 矿藏总量冲突

定稿正文仍有 `sizeScore × 8,000`，但同文又写 3,000–30,000。最高优先级 XLSX「成长与容量」给出 score 25–320 对应 3,000–30,000 的区间端点，中间样例与线性映射取整一致。因此采用 `round(3000+(score-25)*27000/295)`，不采用过时的 ×8,000。生成测试验证总量守恒与所有边界。

## 004 · 暂定生成与表现参数

以下是本版明确标注的实现配置，不是已获确认的新增经济规则：

- 九个 Region 的中文名字、星系命名、行星外观为表现层命名。
- 未给尺寸抽取分布，暂在 score 25–320 均匀抽取，按 XLSX 尺寸边界归类。
- 每球抽取 3–5 矿种，无放回抽取，稀有度权重严格用 XLSX 的 10/5/2/1；母星先保证铁铀。
- 浓度数值未确定，本版不生成浓度加成；总矿藏暂在抽中矿种之间等分并保留余数，保证总量准确。
- 不猜测航行速度或局部/全局距离换算。当前 DU 是银河坐标边长的几何度量，只供星图查看，不能用于未来航行经济结算，v0.5 必须另定单位和公式。
- 起始碎片按计划保留为显式配置 0，未投入任何可消耗玩法。原文 25,000 星币与初始舰船只读展示。

参数集中在 `packages/game-data/world-config.ts`。生产/侦察版本前应补充浓度、尺寸概率、矿种数量和新手库存配置；改变后只影响新世界或通过明确迁移更新旧档，禁止静默重掷。

## 005 · 持久化与迁移

认证表由所固定版本 Better Auth 的迁移计划生成后保存为 001 SQL；运行时只执行版本化 SQL，不自动同步 schema。存档是按账户隔离的 JSONB 世界快照，含 seed/数据/存档/生成器版本；删除保留审计和软删除标记。本阶段无资源变更，不提前创建战斗/生产表。槽位限制使用用户行锁与数据库唯一索引。迁移受 advisory lock 保护，进程中断时整份 SQL 回滚。

Docker PostgreSQL 数据在独立卷中，卷不等同于仓库或云环境快照。未验证跨任务 Docker 卷恢复；发布前应另设数据库备份与恢复策略。不要把当前实例测试等同于远程部署。
